# TimesQuest architecture

`core` is a Java 17 library with no Android or network dependencies. LearningEngine validates all factors at construction, provides unique choices and explanations, maintains 144 directed fact records, selects unseen/weak/due facts and serialises a versioned atomic snapshot. Mastery is three consecutive correct unassisted first answers. Wrong-answer retries and hints never upgrade that first attempt. Response duration is bounded to ten minutes and is not a pass/fail threshold. Review intervals increase from one day to a maximum 32 days; mistakes return after one minute.

`app` uses native Android controls and Canvas illustration. MainActivity coordinates navigation, five-step missions and explicit parent access. SceneView renders original mode-specific characters and environments; ArrayView draws exact row/column counts with an equivalent accessibility description. GameStore retains private SharedPreferences. Question state and the learning snapshot are written in one editor transaction to prevent duplicate first attempts after interruption. Mission completion removes the active session in the same transaction as its crystal reward.

The four islands expand mixed practice through tables 2, 5, 9 and 12. Their crystal thresholds are 0, 2, 4 and 6. Free table practice includes every table immediately, including mixed 1–12 practice. The first three mission types are free. Debug builds expose all modes and explicitly label this development access; release builds require an Amazon entitlement for the additional modes and islands.

Game modes have distinct scenes and actions: friendly spell answers shrink a monster; lock answers reveal treasure; platform answers move Pip; race answers advance a car and can report elapsed answer time; kitchen scoops build a numerical total before serving; circuits assemble a robot. These remain a first implementation of the requested adventure rather than a playtested premium content library. Unique story text per island and mission intro is bundled. Reduced movement freezes animation and native controls support accessibility services.

Voice narration uses Android TextToSpeech only with a non-network voice. Answer recognition uses createOnDeviceSpeechRecognizer on API 31+ after runtime capability detection, a parent setting and RECORD_AUDIO permission. An explicit tap starts one recognition session; another tap stops it, and a timer cancels after eight seconds. Backgrounding cancels recognition. No waveform, recording or transcript is persisted. English number words and the seven requested commands are parsed locally. No online recognition fallback or external AI service is used. Existing Fire OS devices without these services use complete touch controls.

The `amazon` flavour contains the actual Amazon SDK 3.0.9 adapter. The public AppstoreAuthenticationKey.pem is required; without it the UI reports the store unavailable and SDK calls are skipped. Prices come from ProductData. Purchase submission never creates an entitlement. Successful non-consumable receipts, cancellations and completed paginated restoration update a user-scoped local cache. Restore request IDs reject stale snapshots. The last confirmed user is cached for offline ownership; a supported account change replaces the scope. The pure EntitlementRestore reducer tests account/product isolation, cancellation and receipt idempotency. The `standalone` flavour contains no purchase implementation or network permission.

The static `website` is independent of the APK. Build-time generated HTML is crawlable without JavaScript. Its array example is an optional progressive enhancement. The site has no forms, cookies, analytics, remote fonts or account integration. Local output is noindex until release configuration is explicitly supplied. There are no made-up offers, reviews, publisher details or live Appstore links.

GameText and LocaleRegistry provide resource-driven educational grammar, ICU plurals, number formatting, a parent language selector and localised voice commands. Only base or explicitly reviewed/staged packs load in release. UK English is the base; US English is an unreviewed debug-only preview and the other ten packs are incomplete. Source and target hashes bind approval records to the reviewed content. No human/device language approval is claimed.

SessionSnapshot validates a complete persisted mission before applying it. Explicit pause survives foregrounding, completion rewards are idempotent, and parent authorization expires after two minutes or on backgrounding. Protected actions recheck authorization even when an old dialog remains visible. Responsive scene/question panels support tablet landscape, phone scrolling and large text.

The billing adapter separates the production SDK gateway from a recording host-test transport. Confirmed account/product availability gates checkout; pending purchases never unlock content. Paginated restoration commits at the final page, stale responses cannot replace a newer account state, and durable ownership is saved before fulfillment notification. Actual SDK response-model tests cover these paths without contacting Amazon or charging a customer.

Known scope gaps include real store transactions, actual speech-service compatibility, packaged spoken narration, a content authoring UI, broad playtested mission variation, physical-device benchmarks and a certified Fire support list. Host JVM behaviour tests and native Skia layout renders provide regression coverage but do not resolve these gaps. Read submission-readiness.md before describing the project as a release.
